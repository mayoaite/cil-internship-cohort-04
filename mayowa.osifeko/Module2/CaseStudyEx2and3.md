# Case Study Exercise 2 – Functional and Non- Functional Requirements
## First Step Project Business Objectives
The object of the plan is to increase sales by at least 15% by providing the customers with other avenues of placing orders—by phone or online.
### Functional requirement
1.	System must be	 able to add new users - **Business**
2.	System must record customer order - **Business**
3.	System must generate invoices **Administrative**
4.	System must allow for staff to edit/update details of an order via the website **Administrative**
5.	System should allow for the payment terms to be varied **Administrative**
6.	System must interface with the payroll system **Business**
### Non-functional requirement
1.	System must allow for anyone to be able to add themselves to the platform – **Usability.**
2.	System must be able to record up to 50 orders per day - **Performance**
3.	System must be able to send invoices automatically as orders are received - **Performance**
4.	System must be able to generate new invoices as orders are updated - **Scalability**
5.	System must allow for a specific set of people (super admins (Production Manager)) to view all orders. – **Security**
# Case Study Exercise 3 – Prioritizing Requirements
### Must have
-	Create a new account: System must be able to add new users.
-	Record customer orders.
-	System must allow office staff to edit order.
-	System must allow office staff to print and/or mail invoices to customers.
### Should have
-	Users should be able to create their own accounts.
-	System should generate invoices.
-	System should automatically send a weekly report of unpaid invoices to MD.
-	System should make it possible to vary the payment terms on the invoices.
-	System should interface with the company’s payroll system.
### Could have
-	System could allow the Production Manager to be able to view all customer orders so that she can plan production.
### Won’t have this time
-	System will be able to record payments.
